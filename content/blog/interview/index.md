### C++
存储相关的cpp八股「美团ai infra —— 存储方向」
- 内存分区模型
程序运行时，内存通常分为如下：
表格markdown

|区域	|存什么	|生命周期|管理方式
|------|------|------|------|
|栈（stack）|	局部变量、函数参数、返回地址	|随函数调用自动创建/销毁|	编译器自动
|堆（heap）|	new/malloc 动态分配的内存	|手动申请、手动释放|	程序员手动|
|全局/静态区	|全局变量、静态变量	|程序启动到结束|	编译器/系统
|常量区	|字符串字面量、const 常量	|程序启动到结束	|只读|
|代码区	|可执行指令（函数体）	|程序启动到结束	|只读|
其中全局/静态区常再细分为：

.data 段：已初始化的全局/静态变量

.bss 段：未初始化（或初始化为 0）的全局/静态变量

常量区通常归入 .rodata（只读数据段）。

栈的大小收到平台限制，通常在 1MB 到 8MB 之间。因此大数组的分配应该放在堆上，否则可能栈溢出。

- 内存序
  - 为什么需要memory order
```c++
int data = 0;
bool ready = false;

// Thread 1
data = 42;
ready = true;

// Thread 2
if (ready) {
    cout << data;
}
```
上面的代码看似正确，实际运行编译器和 CPU 为了优化，可能对独立内存操作进行重排。因此为了保证多线程操作的正确性，核心问题就是一个线程对内存的修改，另一个线程什么时候能够可靠地观察到？因此 C++ 需要一个内存模型来规定：
```
哪些操作可以重排？
哪些操作必须保持顺序？
什么时候一个线程的写入对另一个线程可见？
```
Memory Order 就是在这个模型下，对 atomic 操作施加不同强度的顺序/同步约束。


Memory Order的五个等级：
```c++
memory_order_relaxed
memory_order_consume
memory_order_acquire
memory_order_release
memory_order_acq_rel
memory_order_seq_cst
```

memory_order_relaxed 只保证原子操作本身的原子性，不提供 acquire/release 意义上的同步和 happens-before 关系。
常用于计数器
```c++
std::atomic<int> cnt{0};

void worker() {
    cnt.fetch_add(1, std::memory_order_relaxed);
}
```

- volatile关键字
volatile 的作用是禁止编译器对该变量的访问进行优化，每次读取都必须从内存重新读取，每次写入都必须真正写回内存。

volatile的定位是处理"单线程视角下，值会被程序之外的东西改变"的场景。
1. 硬件寄存器
```c++
volatile uint32_t *status = (volatile uint32_t *)0x40000000;
while ((*status & 0x01) == 0) { }  // 等待硬件置位
```
硬件会在程序之外改这个值，编译器不能假设它不变。
2. 中断服务程序共享的变量
```c++
volatile bool data_ready = false;

void ISR() { data_ready = true; }   // 中断里改

int main() {
    while (!data_ready) { }          // 主循环里等
}
```
主循环里没有任何代码改 data_ready，编译器会误以为它永远不变，volatile 阻止这种误判。

3. 内存映射 I/O、setjmp/longjmp 相关变量等

- extern "C"关键字
作用：C++ 为了支持函数重载，会对函数名做名称修饰（name mangling）——把参数类型等信息编码进符号名。比如：
```c++
// C++ 里
void foo(int);
void foo(double);
```
编译后符号名可能变成 _Z3fooi 和 _Z3food 这样的形式，这样链接器才能区分两个重载。

而 C 语言不支持重载，函数名不做修饰，foo 编译出来符号名就是 foo。

问题来了：C 代码编译出的目标文件里，函数符号是 foo；C++ 代码去调用时，编译器按 C++ 规则生成调用指令，去找 _Z3fooi，结果链接器找不到符号，报错类似：
```
undefined reference to `foo(int)'
```
extern "C" 就是告诉 C++ 编译器：这个函数按 C 的规则来——不要做名称修饰，用原始名字生成符号。
常见用法：
```c++
//声明单个或几个 C 函数
extern "C" void c_function(int);
extern "C" int  c_add(int a, int b);
//花括号批量
extern "C" {
    void c_func1(void);
    int  c_func2(int);
    void c_func3(double);
}
//写头文件让 C 和 C++ 都能用
// mylib.h
#ifdef __cplusplus
extern "C" {
#endif

void c_function(int);
int  c_add(int a, int b);

#ifdef __cplusplus
}
#endif
```
#### 智能指针

| 类型 | 说明 |
|------|------|
| `unique_ptr` | 独占所有权，不可拷贝，可移动 |
| `shared_ptr` | 共享所有权，引用计数，控制块 |
| `weak_ptr` | 弱引用，解决循环引用，不增加引用计数 |

- **底层实现**：
  - `unique_ptr`：封装裸指针，禁用拷贝构造/赋值，移动语义转移所有权
  - `shared_ptr`：包含两个指针（裸指针 + 控制块指针），控制块包含引用计数（use_count）和弱引用计数（weak_count）
  - `weak_ptr`：通过控制块访问对象，调用 `lock()` 返回 `shared_ptr`

#### move 语义

- `std::move` 本质是 `static_cast<T&&>`，将左值转为右值引用
- 触发移动构造函数/移动赋值运算符，避免深拷贝
- 移动后原对象处于"有效但未指定"的状态

#### 类的多态和继承

- **静态多态**：函数重载、模板
- **动态多态**：虚函数、虚表（vtable）、虚指针（vptr）
- 虚函数表在编译期生成，每个类一张；vptr 在构造时设置
- 纯虚函数 → 抽象类，不可实例化

#### 模板

- 函数模板、类模板、可变参数模板（C++11）
- 模板特化（全特化、偏特化）
- SFINAE（Substitution Failure Is Not An Error）
- C++20 Concept

#### vector vs list（阿里 PolarDB 二面）

| 特性 | `vector` | `list` |
|------|----------|--------|
| 底层结构 | 连续内存数组 | 双向链表 |
| 随机访问 | O(1) | O(n) |
| 插入/删除（中间） | O(n) | O(1)（已知迭代器） |
| 内存占用 | 紧凑，少 | 每个元素额外两个指针 |
| 缓存友好 | ✅ 高 | ❌ 低 |

#### malloc 和 mmap

- **malloc**：C 标准库分配器，小内存用 brk/sbrk 扩展堆，大内存（>128KB）用 mmap
- **mmap**：内存映射，直接映射文件或匿名映射到进程地址空间
- 区别：malloc 管理用户态自由链表，mmap 是系统调用

#### False Sharing（伪共享）

- 多核 CPU 缓存行（通常 64B）失效问题
- 不同线程修改同一缓存行的不同变量 → 缓存一致性协议导致频繁失效
- 解决：缓存行对齐（`alignas(64)`）

#### 语法特性

- **const 的用法**：
  - `const int`：常量
  - `const int*`：指向常量的指针（指针可变，值不可变）
  - `int* const`：常量指针（指针不可变，值可变）
  - `const int* const`：两者都不可变
  - `const` 成员函数：承诺不修改对象

### 场景预设

#### 内存池

- 预分配大块内存，避免频繁 malloc/free
- 实现方式：固定大小块分配、伙伴系统、slab 分配
- 应用：高频小对象分配场景（如游戏引擎、数据库）

#### 缓冲池（Buffer Pool）

- 数据库核心组件，管理磁盘页与内存页的映射
- 核心机制：LRU/K 替换策略、脏页回刷、预读
- 关键问题：并发控制（Page Latch）、崩溃恢复

#### 线程池

- 复用线程，避免频繁创建/销毁
- 核心组件：任务队列、工作线程、线程管理
- 关键设计：任务窃取（Work Stealing）、动态扩缩容

#### 无锁结构（Lock-Free）

- 基于 CAS（Compare-And-Swap）原子操作
- ABA 问题：使用 tagged pointer 解决
- 典型实现：无锁队列（Michael-Scott Queue）、无锁栈
